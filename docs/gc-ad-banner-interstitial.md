# 挖个方块 · Banner / 插屏广告策略（待 adUnitId 后实现）

> 状态：**设计定稿，暂不写业务接线**。  
> 实现前提：`utils/ad-manager.js` 的 `AD_UNIT_IDS.banner` / `AD_UNIT_IDS.interstitial` 填入真实流量主 ID。  
> 激励视频（Rewarded）已有多点位接线，本文只规范 **Banner** 与 **插屏（Interstitial）**。  
> 对齐：[`gc-economy-design.md`](./gc-economy-design.md) 铁律 3「广告只加速」；打扰型广告不参与金方块产出。

---

## 1. 产品定位

| 类型 | 玩家感知 | 商业角色 | 与激励视频区别 |
|------|----------|----------|----------------|
| **激励视频** | 自愿换奖励 | 金币加速 | 主动点看 |
| **Banner** | 逛页时的条幅 | 被动曝光、低频 | 不挡对局 |
| **插屏** | 局后全屏挡一下 | 被动曝光、单价较高 | 只在自然断点 |

**原则**

1. **对局中零打扰**：`game` 场景内不出现 Banner / 插屏。  
2. **挑战链路零插屏 / 零 Banner**：分享、应战、挑战结算全程跳过（保护社交转化）。  
3. **能关就关**：Banner 短时展示后自动隐藏；插屏必须可关闭。  
4. **月卡预留**：未来 IAP「清静畅玩」关闭的是 Banner + 插屏，**不关闭**自愿激励视频。

## 3. Banner 策略

### 3.1 允许出现的场景

| 场景 | 时机 | 离开时 |
|------|------|--------|
| 首页 Hub | `onEnter` 后延迟 **1.5～2s** 再 `showBanner` | `onExit` / 切场景 → `hideBanner` |
| 关卡选择 `stageSelect` | 同上延迟 | 同上；弹出场费/解锁 Toast 时可先 hide |
| 关卡广场 `plaza`（可选，二期） | 列表态延迟展示 | 开打开打弹窗、进 game → hide |

### 3.2 禁止出现的场景

- `game` 对局（含开场垃圾掉落、SETTLING 塌陷）  
- `stageResult` / `stageFail` 撒花与主按钮操作期（避免与插屏叠）  
- `challenge` / `challengeResult` 及分享卡流程  
- `shop` 购买确认瞬间（可整页不用 Banner）

### 3.3 频率与形态

沿用 / 微调 `FREQUENCY_CONFIG.banner`：

| 规则 | 值 | 说明 |
|------|-----|------|
| 展示时长 | **15s 自动 hide** | 已实现，必须保留 |
| 两次 show 间隔 | ≥ 30s | 已实现 |
| 单次进入场景 | **最多 show 1 次** | 实现时在场景侧加「本页已展示」标记，避免 30s 后又弹 |
| 位置 | 底部安全区 | 已有 `_getBannerStyle` |

### 3.4 实现备忘（adId 就绪后）

1. `home-scene` / `stage-select-scene`：`onEnter` → `setTimeout` → `adManager.showBanner()`。  
2. `onExit` / `onHide`：`hideBanner`（`game.js` 已有 AppHide 隐藏，保留）。  
3. 未配置 ID 时保持现状：静默跳过，不 Toast。

## 4. 插屏策略

### 4.1 允许出现的断点

| 断点 | 建议时机 | 备注 |
|------|----------|------|
| 闯关失败 → `stageFail` | 进入失败页后 **0.8～1.2s**（成绩已可见） | 优先开：失败情绪下可接受 |
| 闯关成功 → `stageResult` | 撒花开始后 **≥1.5s**，或点「返回关卡」**之前** | 勿盖住「下一关 / 看广告领金币」首帧 |
| 经典结算 `result` | **保持**现有：前 5 局免、每 6 局 1 次 | 已接线 |

### 4.2 禁止出现的断点

- 对局中任意时刻  
- 激励视频播完立刻再插屏（同一次结算二选一：有激励按钮交互时，插屏延后到「离开结算」）  
- 挑战创建 / 应战 / 挑战结算  
- 工坊编辑、试玩返回编辑  

### 4.3 频率（局级 + 模块级双闸）

**局级（闯关，实现时新增计数，建议键 `gc_stageGameCount` 或复用全局对局计数）**

| 规则 | 值 |
|------|-----|
| 前 N 局免费 | **N = 5**（与经典一致） |
| 之后每 M 局 1 次 | **M = 6** |
| 挑战局 | **不计入、不展示** |

**模块级（已有 `FREQUENCY_CONFIG.interstitial`）**

| 规则 | 值 |
|------|-----|
| 两次插屏最小间隔 | **180s** |
| 单会话上限 | **3**（可后续调到 4～5，先严后松） |

两闸同时满足才 `showInterstitial`。

### 4.4 与结算页激励按钮的关系

同一结算页若展示「看广告再领一份」：

- **优先保证激励入口可点**  
- 插屏改为：用户点「返回关卡 / 返回」时再尝试；或撒花后延迟且检测无激励弹层  

避免：进结算 → 插屏盖死 → 玩家关广告后找不到领奖按钮。

```

  ├─ 激励视频：入场 / 重试 / 双倍 / 每日福利（自愿）

  └─ Banner + 插屏：关闭（ad-manager 增加 isNoPassiveAds() 开关即可）
```

## 6. 上线顺序（adId 就绪后）

| 步骤 | 内容 | 验收 |
|------|------|------|
| **0** | 后台申请并填写 `rewardedVideo` / `banner` / `interstitial` 三个 ID | 开发者工具无「未配置跳过」日志（或仅剩填充失败） |
| **1** | 只开激励视频（已接线） | 免费入场等按钮出现且能播 |
| **2** | 接插屏：`stageFail` + `stageResult`（按 §4） | 前 5 局无；第 6/12… 局后可见；挑战路径无 |
| **3** | 接 Banner：首页 + 选关（按 §3） | 15s 自消；进对局必消失 |
| **4** | 看 3～7 日留存 / 差评，再调 M 或关掉 Banner | 文档修订频率表 |

若只能先开一种打扰型：**优先步骤 2 插屏**（eCPM 与可控性通常优于 Banner）。
