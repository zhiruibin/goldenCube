# 挖个方块 · 章节与关卡主题设计（定稿）

> 规模：**10 章 × 10 关 = 100 关**。布局：10 列 × 20 行，`#`=垃圾，`.`=空；行号 0=顶、19=底。
>
> **难度**：章间递增、章内递增（见 §1.2）。**金币阈值**每关写死：`coinThreshold T = minLines × 2`（与 `gc-economy-design.md` 效率结算一致）。
>
> **v3 布局重构（2026-08）**：全章按「正形剪影 + 抬升/凌空 + 高位搭梯」重摆；数据以 `data/stages-v1.json` 为准。下方 §3 起部分 ASCII 示意可能滞后，请以 JSON / 预览页为准。

## 1. 总则

### 1.0 关型与乐趣原则（v3）

引擎规则前提：**粘性垃圾、满行才消、消行后非垃圾块按列塌陷（垃圾作屏障不移动）、塌陷可连锁**。难度应来自几何与决策，而不是「堆满近满行」。

| 关型 | 含义 | 用法 |
| --- | --- | --- |
| **silhouette（正形剪影）** | 垃圾块本身拼出**本章主题**轮廓（数字/字母/花/兽等）；可整体离地 1～4 行 | **主菜**，前几章即以此教学 |
| **ladder（高位搭梯）** | 主题碎片浮空（旗尖/花瓣/星点/冠尖）+ 下方真空或稀疏踏石 | 每章 1～2 关顿悟；星象章加重 |
| **channel（负形廊道）** | 墙体夹出通道（少用） | 地宫等少数关 |

**明确少做**：大实心矩形再抠洞；整坨钉死第 19 行导致只能从底消；与章节主题无关的抽象散点。

**主题与抬升**：形必须可读出章节主题；**建筑/车辆偏贴地**，**花田/星象/几何/金殿偏凌空**。抬升是为了腾出搭梯空间，不是换一套无主题乱堆。

**前几章也一并重构**：第 1 章起就教「读剪影 / 填洞」；中段插入主题浮空搭梯；不要把「好课」留到后期。

### 1.1 摆关硬约束

1. 禁止满行 `##########`
2. 有垃圾的行至少 1 个 `.`
3. 顶部留空：普通贴地剪影顶垃圾行 ≥ 5～6；**抬升 / ladder / Boss** 可到 ≥ 4
4. 固定布局、标准 7 块可解
5. `minLines` = 含垃圾行数；`garbageCount` = `#` 数；**`coinThreshold`（T）= minLines × 2**
6. 章内 `minLines` 非降；同 `minLines` 时 `garbageCount` 尽量非降（ladder 关可用加稀疏行升 `minLines` 满足）
7. 递进补块优先加顶行 / 沿轮廓加密度，**禁止填死抬升真空**

### 1.2 难度递进规则（硬性）

| 维度 | 规则 |
| --- | --- |
| **章内** | 第 k+1 关不比第 k 关更容易：先比 `minLines`（非降），相同则比 `garbageCount`（非降）；顶垃圾行可随难度上移（数值变小） |
| **章间** | 第 n+1 章的入门 `minLines`、章均 `minLines`、章 Boss `minLines` 均 ≥ 第 n 章对应值 |
| **速度** | 下落间隔随章递减（1000→750 ms），同章内不变（难度主要靠盘面） |

### 1.3 金币阈值（通关结算）

结算公式（通关后一次性，失败不发）：

```
T = coinThreshold = minLines × 2
lines' = clamp(实际消行, minLines, T)
金币 = clamp(20 + round((T − lines') / (T − minLines) × 80), 20, 100)
```

| 实际消行 | 金币 |
| --- | --- |
| = minLines（理论最优） | **100** |
| 介于 minLines 与 T 之间 | 21～99（线性） |
| ≥ T | **20**（保底，再差也一样） |

因此：**T 越大，最优与保底之间的「刷优空间」越宽**；高难关（高 minLines）自然有更高 T，鼓励少消行。日结上限等仍见经济文档。

**示例**（minLines=4 → T=8）：消 4 行=100，5=80，6=60，7=40，≥8=20。
